# v0.17.1: Reproducibility and offline Jev research readiness

Repository release: v0.17.1 (26 September 2026). Current paper: v0.17.0.
This is a repository and experimental-methods release, not a new paper or new
empirical result. The 30-page v0.17.0 preprint and its historical findings remain
unchanged; the v0.14.0 DOI is not reassigned.

## Included updates

- Elevated README and corrected current navigation/citation metadata.
- Complete canonical Apache-2.0 license, attribution in NOTICE, and a clean-environment
  reproducibility guide with isolated v0.16.0/v0.17.0 historical audit replay.
- Original opt-in Jev contract-fidelity and evidence-reconstruction scaffolds, with
  frozen evidence, authority challenges, mutations, nuisance variants, compositional
  holdouts, repetition policy, failure accounting and descriptive reporting.
- Append-only dated adjudication records and a separately preserved author-audit route.
- Author-approved evidence-v2 successor addressing 14 triaged issues from 30 flagged
  units. It changes 159 excerpt occurrences and five question instructions, records
  all 1,654 label decisions and preserves all 60 expected pair deltas.

The evidence-v2 route is author review of AI-assisted work. The author accepted
216 AI-assisted assessments and approved the correction proposals. It is not
independent review, an unassisted author pass or a completed delayed consistency
study. Those original routes remain preserved. Added scenario facts are authored
synthetic stipulations, not reconstructed historical evidence.

## Validation and boundaries

Core repository validation remains credential-free and deterministic. Original
release snapshot checks cover seven historical tags, 854 sealed artifacts and
98 immutable working copies. v0.17.0 retains 30 unchanged research artifacts and
three separately hashed current-navigation documents. Historical audits reproduce
exactly, including their published exceptions.

The offline Jev suites validate byte-preserving inputs/outputs, response rejection,
metrics, controlled changes, nuisance relationships, review records and freeze
integrity. Evidence-v2 dry-run/mock validation covers 94 packets × three repetitions
= 282 scheduled requests and 4,962 determinations. Mock outputs are plumbing checks,
not evidence of Jev accuracy. No live Jev call was made for these updates.

Independent interpretation, ecological validity, provider performance and public-case
transfer remain unestablished. Live evidence-v2 execution requires a separately
reviewed bridge and compatible provider configuration. JEV-TAE-6 remains deferred.

## Release integrity and reproduction

`v0.17.1-manifest.json` hashes every tracked file in this repository snapshot except
itself; the tag anchors the manifest. It includes prior releases without rewriting
them. The attached repository TAR is exported from the exact tagged commit;
SHA256SUMS records the attached asset hashes. Neither is a rebuilt v0.17.0 paper.

After fetching the tag, verify it with:

```sh
python scripts/verify_repository_release.py --ref v0.17.1
python scripts/validate_repository.py
```

For environment setup and offline test commands, see `docs/REPRODUCIBILITY.md`.
The new standalone snapshot check validates the v0.17.1 Git snapshot; it does not
require future development working files to remain identical to this release.
